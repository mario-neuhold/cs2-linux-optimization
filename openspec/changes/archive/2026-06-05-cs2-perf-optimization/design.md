# Design: CS2 Performance Optimization

## Technical Approach

Apply five isolated, independently reversible system changes using the lowest-privilege
mechanism available for each: user systemd services where possible, global env vars only
where truly system-wide routing is required, and plain config files for CS2 tuning.
All changes persist across reboots. No kernel parameters are modified.

## Architecture Decisions

### Decision: CPU Governor Persistence Mechanism

| Option | Tradeoff | Decision |
|--------|----------|----------|
| `powerprofilesctl set performance` oneshot service | Uses already-active power-profiles-daemon; cleanest integration | ✅ CHOSEN |
| `cpupower frequency-set -g performance` systemd service | Works but bypasses power-profiles-daemon, causing conflicts | Rejected |
| udev rule on AC power | Conditional on AC plug — user wants always-on | Rejected |

**Rationale**: `power-profiles-daemon` is already active and manages `intel_pstate`.
Using `powerprofilesctl` avoids driver conflicts and is the supported interface on this system.

### Decision: GPU Routing Scope

| Option | Tradeoff | Decision |
|--------|----------|----------|
| Global `/etc/environment` vars | All apps use NVIDIA; simple, persistent | ✅ CHOSEN |
| Per-app wrapper scripts | Surgical but manual for every new app | Rejected |
| `prime-select nvidia` | Cleaner but requires nvidia-prime package (not installed) | Rejected |

**Rationale**: User explicitly wants GTX 1650 as the global primary GPU, not per-app.
`/etc/environment` is the correct PAM-sourced global scope.

### Decision: Gamemode Daemon Fix Strategy

| Option | Tradeoff | Decision |
|--------|----------|----------|
| `systemctl --user enable gamemoded` | Correct scope (user service), `gamemoded -t` already passes | ✅ CHOSEN |
| System-level service | Overkill; unit file lives in systemd/user | Rejected |

**Rationale**: `gamemoded` ships as a user service (`/usr/lib/systemd/user/gamemoded.service`).
It is installed and functional (`gamemoded -t` passes), just not enabled at login.
`loginctl enable-linger` ensures it starts without an active session.

## Implementation Details

### 1. GPU Primary NVIDIA — `/etc/environment`

Append to `/etc/environment`:
```
__NV_PRIME_RENDER_OFFLOAD=1
__GLX_VENDOR_LIBRARY_NAME=nvidia
__VK_LAYER_NV_optimus=NVIDIA_only
DRI_PRIME=1
```
Requires reboot to take effect. Install `mesa-utils` to verify with `glxinfo`.

### 2. CPU Performance Governor — systemd system service

File: `/etc/systemd/system/cs2-performance-governor.service`

```ini
[Unit]
Description=Set CPU governor to performance
After=power-profiles-daemon.service
Requires=power-profiles-daemon.service

[Service]
Type=oneshot
ExecStart=/usr/bin/powerprofilesctl set performance
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
```

Enable: `sudo systemctl enable --now cs2-performance-governor.service`

### 3. Gamemode — enable user service + gamemode.ini

```bash
systemctl --user enable --now gamemoded
loginctl enable-linger $USER   # start at boot without active session
```

File: `/etc/gamemode.ini`

```ini
[general]
renice=10
ioprio=0
inhibit_screensaver=1

[filter]
whitelist=cs2
```

> Note: `renice` in gamemode.ini is the absolute nice value delta (positive = lower nice number).
> Setting `renice=10` results in nice=-10 for the game process.

### 4. CS2 Launch Options (Steam App ID 730)

Set in Steam → Counter-Strike 2 → Properties → Launch Options:

```
gamemoderun %command% -novid -high -threads 4 +fps_max 0 +exec autoexec
```

### 5. CS2 Autoexec.cfg

File: `~/.local/share/Steam/steamapps/common/Counter-Strike Global Offensive/game/cfg/autoexec.cfg`
(Directory does not exist yet — must be created.)

```
// CS2 Performance Autoexec
// Generated by cs2-perf-optimization

// FPS
fps_max 0
cl_showfps 1

// Rendering
r_dynamic 0

// Network (128-tick)
rate 786432
cl_cmdrate 128
cl_updaterate 128
cl_interp_ratio 1
cl_interp 0
```

## File Changes

| File | Action | Description |
|------|--------|-------------|
| `/etc/environment` | Modify | Append 4 NVIDIA GPU routing vars |
| `/etc/systemd/system/cs2-performance-governor.service` | Create | Oneshot systemd service for performance governor |
| `/etc/gamemode.ini` | Create | Gamemode tuning: renice, ioprio, screensaver |
| `~/.local/share/Steam/.../game/cfg/autoexec.cfg` | Create | CS2 FPS + network settings (dir must be created) |
| Steam App 730 launch options | Modify | Set via Steam UI → Properties → Launch Options |

## Testing Strategy

| Capability | Verification Command | Expected Result |
|---|---|---|
| GPU routing | `glxinfo \| grep "OpenGL renderer"` | Contains "NVIDIA GeForce GTX 1650" |
| CPU governor | `cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor` | `performance` |
| Power profile | `powerprofilesctl` | `performance` marked with `*` |
| Gamemode daemon | `systemctl --user is-active gamemoded` | `active` |
| Gamemode self-test | `gamemoded -t` | Exit code 0 |
| CS2 launch | Launch CS2, check FPS counter in-game | > 60 FPS stable |
| Autoexec | CS2 console: `fps_max` | Returns `0` |
| Network | CS2 console: `net_graph 1` | cmdrate/updaterate = 128 |

## Rollback Plan

| Component | Rollback |
|---|---|
| GPU vars | Remove 4 lines from `/etc/environment`, reboot |
| CPU service | `sudo systemctl disable --now cs2-performance-governor.service` |
| Gamemode | `systemctl --user disable --now gamemoded` |
| CS2 options | Clear field in Steam → CS2 → Properties → Launch Options |
| Autoexec | `rm ~/.local/share/Steam/.../game/cfg/autoexec.cfg` |
